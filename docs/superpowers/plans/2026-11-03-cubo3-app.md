**Goal:** App Cubo³ (Android + navegador) completo sobre a API já publicada em `https://cubo3.kerlonr.com.br`: login multiempresa, painel, impressões com confirmação, catálogo com arquivos, estoque, vendas, calculadora offline, fila offline, notificações sem Firebase e atualização pelo próprio servidor.

**Architecture:** Um app Flutter em `app/` com `provider` (padrão do Meu Frete). Uma camada `api/` concentra HTTP, sessão, cache de leitura e fila offline; as telas só falam com ela. Cálculo de custo duplicado em Dart (`dominio/custos.dart`) para a calculadora funcionar sem internet, testado contra os mesmos números do servidor. Notificações por serviço em primeiro plano (Android) ligado ao WebSocket `/api/ao-vivo`.

**Tech Stack:** Flutter 3.47 / Dart 3.13 (`D:\dev\flutter\bin\flutter.bat`), provider, http, intl, shared_preferences, flutter_secure_storage, uuid, file_picker, desktop_drop, url_launcher, fl_chart, web_socket_channel, flutter_foreground_task, flutter_local_notifications, package_info_plus. Fonte Inter empacotada.

**Spec:** `docs/superpowers/specs/2026-11-02-cubo3-design.md` (seções 2–4, 8–11). Contrato da API: `server/app/**/rotas.py` + `server/tests/` (verdade sobre campos e erros) e a tabela abaixo.

- Base da API: Android `https://cubo3.kerlonr.com.br`; web usa a própria origem (`Uri.base.origin`). Editável em Configurações (avançado).

- Segredos fora do git: keystore e `android/key.properties` (já no `.gitignore` como `*.jks` e `key.properties`).

## Contrato da API (resumo)

Cabeçalhos: `Authorization: Bearer <acesso>` + `X-Empresa: <id>`; em PUT de cadastro, `X-Alterado-Em: <ISO UTC>` (a edição mais antiga que a última gravação é ignorada). Erros: JSON `{"detail": "..."}`.

| Área | Rotas |
|---|---|
| Sessão | `POST /api/auth/login {email,senha}` → `{acesso, refresh, trocar_senha}`; `POST /api/auth/refresh {refresh}`; `POST /api/auth/senha {atual,nova}` (devolve tokens novos); `GET /api/eu` → `{id,nome,email,trocar_senha,empresas:[{id,nome,papel}]}`. Login: 5 falhas/15 min → 429 |
| Empresa | `GET/PUT /api/empresa/config` (PUT só dono) `{eficiencia, mao_obra_hora, kwh, reserva, margens[]}`; `GET/POST /api/empresa/membros`, `DELETE /api/empresa/membros/{usuario_id}` |
| CRUD padrão | `GET /api/X?atualizado_desde=&incluir_excluidos=`, `GET/PUT/DELETE /api/X/{id}` para `canais`, `impressoras` (saída `custo_hora`, `tem_api_key`), `filamentos`, `carreteis` (saída `saldo_g`, `preco_kg_real`, `filamento{}`), `insumos` (saída `saldo`), `clientes`, `despesas`, `modelos`, `impressoes` |
| Estoque | `PUT /api/movimentos/{id}`; `GET /api/movimentos?item_tipo=&item_id=`; `POST /api/carreteis/{id}/pesagem {movimento_id, peso_balanca_g}`; `GET /api/estoque` → `{carreteis, filamentos[{total_g,baixo}], insumos[{saldo,baixo}], pecas[{modelo_id,saldo}]}` |
| Catálogo | `GET /api/modelos?busca=&categoria=&tag=&ordem=nome|recentes|mais_vendidos|lucro&periodo_dias=` (saída `custo{material,mao_obra,maquina,insumos,embalagem,total}`, `lucro_unitario`, `estoque`, `vendidos`, `arquivos[]`, `capa_url`); `POST /api/modelos/{id}/arquivos` (multipart `arquivo`, 95 MB, 415 para extensão fora de stl/3mf/gcode/obj/step/stp/png/jpg/jpeg/webp); `GET /api/arquivos/{id}`; `DELETE /api/arquivos/{id}`; `POST /api/arquivos/{id}/link` → `{url}` (link de 10 min, sem login) |
| Calculadora | `POST /api/calculadora` |
| Impressões | `GET /api/impressoes?status=a_confirmar|confirmada|arquivada|descartada`; `POST /api/impressoes/{id}/confirmar {finalidade: venda|pessoal|teste|falhou, pecas_boas, consumos[{carretel_id,gramas}], perdas[], mao_obra_min?, modelo_id?}` (repetir = devolve a mesma); `POST /api/impressoes/{id}/descartar`; `GET /api/impressoes/{id}/miniatura`; DELETE de confirmada → 409 |
| Klipper | `GET /api/impressoras/{id}/ao-vivo` → `{estado, arquivo, progresso 0–1, duracao_s, restante_s, bico, bico_alvo, mesa, mesa_alvo}`; `GET /api/impressoras/{id}/historico?limite=` (itens com `ja_trazido`); `POST /api/impressoras/{id}/historico/{job_id}/trazer`; WS `/api/ao-vivo?token=<acesso>&empresa=<id>` → eventos `{"tipo":"estado", impressora_id, ...}` e `{"tipo":"impressao_terminou", impressao_id, impressora_id, arquivo, situacao}`; cliente pode mandar texto `ping` |
| Vendas | `PUT /api/pedidos/{id}` `{cliente_id?, canal_id?, status?, desconto?, frete_cobrado?, custo_envio?, pago?, forma_pagamento?, obs?, entregue_em?, itens[{id, modelo_id?, descricao, quantidade, preco_unitario}]}` (status `entregue` já entrega = venda rápida; resposta tem `avisos[]`); `GET /api/pedidos?status=&cliente_id=`; `POST /api/pedidos/{id}/status {status}` (entregue só → cancelado; cancelado é final → 409); `GET /api/clientes/{id}/historico` |
| Painel | `GET /api/painel?inicio=&fim=` → `{receita, gastos, resultado, lucro_vendas, por_mes[12], mais_vendidos[5], a_confirmar, estoque_baixo[], horas_impressao, kg_filamento}` |
| Versão | `GET /api/versao` → `{versao, build, apk_url}` (404 sem versão); `GET /baixar` (APK) |

## Review Focus

1. **Sem sinal no meio de uma venda** — Kerlon registra venda rápida no 4G sem cobertura: o app deve aceitar, mostrar "salvo no aparelho, envia quando tiver internet", e a venda chegar ao servidor uma única vez quando a rede voltar (mesmo que o app seja fechado e reaberto). Teste na Task 4.
2. **Token expira com o app aberto** (acesso dura 30 min) — a próxima chamada recebe 401: o app renova com o refresh e repete a chamada sem o usuário perceber; refresh inválido leva ao login sem perder a fila. Teste na Task 3.
3. **Arquivo grande pelo túnel** — STL de 150 MB: o app recusa antes de enviar com "Arquivo maior que 95 MB"; resposta 413 em HTML da Cloudflare também vira essa mensagem, nunca um erro de parsing. Teste na Task 7.
4. **Valores digitados no padrão brasileiro** — "1.234,56", "33,5 g", campo vazio: viram número certo ou erro claro; nunca `FormatException` na tela. Teste na Task 1.
5. **Item excluído aparecendo em histórico** — pedido antigo de modelo excluído e carretel de filamento excluído mostram o nome (o servidor manda `modelo{nome,excluido}` / `filamento{...}`), e excluídos não aparecem nos seletores de nova venda/confirmação. Teste na Task 9.
